`<IPad>` and `<IPadMockup>` cover the current Apple iPad lineup at true
relative sizes - iPad Pro (M5), iPad Air (M4) and the standard iPad (A16).
Each variant gets its real hardware: the Pro's camera pod with LiDAR and
flash, the Air's and iPad's bare single lens with the Touch ID top button, the
Apple Pencil charging strip on the long edge, the Smart Connector dots (on the
back, or sunk into the rail on the A16), the Apple glyph as real vector
geometry centered on the back, the model wordmark below it, drilled speaker
clusters in both short edges, and the front camera in the landscape-top bezel.

In landscape the virtual display swaps to the variant's landscape grid -
1376×1032 on the 13″ iPad Pro - so desktop-class layouts apply.

## `<IPad>` vs `<IPadMockup>`

<BareVsMockup object="IPad" kind="ipad" slot="Screen" />

```tsx
import { MockupCanvas, IPad, IPadMockup } from 'react-3d-mockups'

// The one-liner: its own canvas, with lighting, a ground shadow, drag-to-orbit
// controls and a camera already framed on the object.
<IPadMockup float style={{ height: 520 }}>
  <YourApp />
</IPadMockup>

// The same model with no stage of its own. Inside a canvas you arrange
// yourself it can be posed, animated, lit and joined by anything else.
<MockupCanvas>
  <IPad rotation={[0, 0.4, 0]}>
    <YourApp />
  </IPad>
</MockupCanvas>
```

## Props

Beyond the [shared screen props](/docs/screen-content) and, on the mockup, the
[shared mockup props](/docs/api):

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `variant` | `'ipadpro13' \| 'ipadpro11' \| 'ipadair13' \| 'ipadair11' \| 'ipad11'` | `'ipadpro13'` | Which iPad: Pro 13"/11" (camera pod, Pencil strip, Face ID), Air 13"/11" (single lens, Touch ID top button), or the A16 iPad (single lens, edge Smart Connector). |
| `orientation` | `'portrait' \| 'landscape'` | `'portrait'` | Landscape lays the tablet on its side and swaps the virtual display (for example 1376×1032 on the 13" Pro) with upright content. |
| `statusBar` | `boolean \| StatusBarOption` | `false` | Draw the system status bar across the top of the screen. `true` gives the platform's defaults - iPadOS's, a 24pt strip with the clock at the leading inset and the meters at the trailing one; an object sets the clock, the meters and the ink (`{{ time: '14:05', battery: 0.42, batteryPercent: true, color: '#1c1c1e' }}`). It is placed from this device's own camera cutout and logical grid, so it lines up with the hardware on every variant. See [Status bar](/docs/screen-content#status-bar). |
| `color` | `string` | `'#2b292c'` | Body color. Takes a colorway id from `IPAD_COLORWAYS[variant]` (see [Colorways](#colorways)) or any CSS color. |
| `resolution` | `number` | per variant | Defaults to the variant's logical grid: 1032×1376 (ipadpro13), 834×1210 (ipadpro11), 1024×1366 (ipadair13), 820×1180 (ipadair11, ipad11). |

## Regions

One region: the screen (bare children). Use the explicit
`<IPadMockup.Screen>` slot when you want per-surface overrides -
`surfaceBackground`, `resolution`, `surfaceStyle`. The same slot exists on
the bare `<IPad>`.

## Colorways

Pass a colorway id from `IPAD_COLORWAYS[variant]` for that model's retail
finish, or any CSS color for a custom one. An id wins over a CSS color of the
same name - pass hex if you mean the CSS one.

| Model | Colorway ids (body color) |
| --- | --- |
| iPad Pro 13″, iPad Pro 11″ (`ipadpro13`, `ipadpro11`) | `spaceblack` (`#3a383c`), `silver` (`#d6d8da`) |
| iPad Air 13″, iPad Air 11″ (`ipadair13`, `ipadair11`) | `spacegray` (`#7d7b80`), `starlight` (`#e7e2de`), `purple` (`#e4deea`), `blue` (`#d9e7e8`) |
| iPad 11″ (`ipad11`) | `silver` (`#e9eaec`), `blue` (`#92b3d6`), `pink` (`#f9899c`), `yellow` (`#fbe778`) |
