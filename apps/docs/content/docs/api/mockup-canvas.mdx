`<MockupCanvas>` wraps a react-three-fiber `Canvas` with everything a product
shot needs. Compose it with any device, for example
`<MockupCanvas><Galaxy>...</Galaxy></MockupCanvas>`.

The one-liner `*Mockup` components are built on this stage and accept its
props, including the rendering and accessibility ones (`frameloop`,
`pauseWhenOffscreen`, `dpr`, `time`, `delayCapture`, `gl`, `onCreated`,
`label`, `screenAccessibility`). Two are canvas only: `freeRotation` and
`shadowY`, because a mockup already derives its shadow ground line from the
object's own framing. Reach for `MockupCanvas` when you want those, or when
you are staging more than one device.

The procedural studio light rig is always on. It is what gives every material
its reflections, it costs no network requests (no HDR files are fetched), and a
mockup without it reads as flat untextured plastic - so it is not a prop.

One canvas, two bare devices, one shared studio light rig and shadow plane.
The inspector drives the canvas itself, so every stage prop in the table below
applies to the whole scene - both devices at once. The Galaxy follows the
device rows too; the iPhone beside it keeps the props written into the example,
the way a second object in a scene of your own would.

<MockupExplorer
  component="GalaxyMockup"
  props={{ variant: 's26ultra', color: '#2e3238', camera: { position: [0, 0.5, 8.6], fov: 40 } }}
  arrangement={{
    canvas: { shadowY: -2.35 },
    items: [
      { props: { position: [-1.6, 0, -0.2], rotation: [0, 0.3, 0] } },
      {
        component: 'IPhoneMockup',
        props: { variant: 'promax', color: 'deepblue', position: [1.6, 0, 0], rotation: [0, -0.3, 0] },
      },
    ],
  }}
/>

## Props

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `children` | `ReactNode` | - | Your scene, typically a device such as `Galaxy`. |
| `controls` | `boolean` | `true` | Drag-to-rotate controls around the stage center, plus the [keyboard controls](#keyboard-controls). Vertical rotation stays within the classic orbit clamp by default. With a mouse, a right or middle drag pans; `Home` puts the camera back. |
| `freeRotation` | `boolean` | `false` | Allow the camera to rotate a full 360° vertically - vertical drags continue straight over the top and bottom of the device instead of clamping. |
| `autoRotate` | `boolean \| number` | `false` | Slowly spin the camera around the device. `true` is one revolution a minute; a number multiplies that (`autoRotate={2}` twice as fast, `autoRotate={0.5}` half). Held still under [reduced motion](#reduced-motion). |
| `zoom` | `boolean` | `false` | Pinch zoom on touch and on a trackpad (ctrl/⌘ with a mouse wheel), plus an overlay control: −, the level, +. A plain scroll always passes through to the page. Off by default; on, the canvas owns two-finger gestures on touch screens. |
| `fullscreen` | `boolean` | `false` | Adds an overlay button that expands the mockup to fill the screen via the Fullscreen API (and collapses it back). Off by default. |
| `shadows` | `boolean` | `true` | Soft contact shadow under the device. |
| `shadowY` | `number` | `-2.05` | Y position (world units) of the shadow plane. Grounds the device on its shadow. The mockup wrappers compute this per device. |
| `background` | `string` | - | CSS background of the canvas (color, gradient, or image). Transparent when unset - that is what the checkerboard behind each page's first example is showing through. |
| `camera` | r3f camera | per model | The camera pose. Each `*Mockup` starts from its own framing of its model, and `camera` replaces that framing; `MockupCanvas` on its own starts at `[0, 0.5, 7.4]`, fov 40. Live: change `position` or `fov` later and the camera moves there, looking at the stage center - a dolly or a zoom driven from props. |
| `dpr` | `number \| [min, max]` | `[1, 2]` | Device pixel ratio clamp. Keeps hi-dpi GPU load predictable. |
| `frameloop` | `'demand' \| 'always' \| 'never'` | `'demand'` | When the canvas draws. `'demand'` renders only when something changes (a drag and its damping, zoom, `autoRotate`, `float`, a prop change, a resize), so an idle mockup renders no frames. `'always'` renders every frame, for a `useFrame` animation of your own; `'never'` freezes the canvas. See [Rendering](#rendering). |
| `pauseWhenOffscreen` | `boolean` | `true` | Stop rendering while the canvas is scrolled out of the viewport or the tab is hidden, and resume on return. |
| `time` | `number` | - | Seconds on a clock you own (a video's `frame / fps`). Set, `autoRotate` and `float` follow it instead of the browser's clock, so the same `time` always draws the same picture - see [Exporting](/docs/exporting#video-with-remotion). Reduced motion does not hold them still on your clock. |
| `delayCapture` | `(reason: string) => () => void` | - | Hold an outside capture - a video render, a screenshot - until the picture is complete: called whenever a frame is on its way that is not drawn yet (the renderer starting, a redraw after a change, a screen's content landing), it returns the function the canvas calls once it is. Wire it to Remotion's `delayRender`/`continueRender` - see [Exporting](/docs/exporting#video-with-remotion). While set, the canvas never pauses. |
| `gl` | r3f `gl` props | `{ antialias: true, alpha: true, powerPreference: 'default' }` | WebGL renderer settings, merged over the defaults. Opt into the discrete GPU with `{ powerPreference: 'high-performance' }`. Keep `alpha: true`: screens show through transparent canvas pixels. |
| `onCreated` | `(state) => void` | - | react-three-fiber's `onCreated`, called once with the canvas state (`gl`, `scene`, `camera`, ...) - for example to read `gl.info`. |
| `label` | `string` | per model | Accessible name of the canvas, which has `role="img"`. Mockups default to a description of the model ("3D mockup of a Galaxy S phone"); `MockupCanvas` on its own to "3D mockup". See [Accessibility](#accessibility). |
| `screenAccessibility` | `'hidden' \| 'visible'` | `'hidden'` | Whether screen content is exposed to assistive technology. `'hidden'` marks every screen `aria-hidden` and `inert`, so decorative screen content stays out of the accessibility tree and the tab order; `'visible'` exposes it. |
| `className`, `style` | - | - | Forwarded to the canvas wrapper. |

## More examples

### Zoom controls

`zoom` enables pinch on touch, pinch on a trackpad (or ctrl/⌘ with a mouse
wheel), and an overlay control on both: zoom out, the level, zoom in. A
plain scroll is never captured - two fingers on a trackpad or a bare mouse
wheel over the mockup scroll the page, the way they do anywhere else. The level reads against where
the camera started, and pressing it puts the camera back there. Zooming
clamps to the same distance range as the orbit controls. The control is
self-contained, and it takes its colours and its face from
`--mockup-overlay-bg`, `--mockup-overlay-border`, `--mockup-overlay-fg` and
`--mockup-overlay-font` when the page sets them, so it can wear the page's
own chrome.

<MockupExplorer component="BookMockup" props={{ zoom: true, float: true, color: '#4a2c3f' }} />

### Full-screen view

`fullscreen` adds an overlay button that expands the mockup to fill the whole
screen through the browser's Fullscreen API, with a matching button to collapse
it back. It composes with `zoom`, and works on any mockup.

```tsx
<BookMockup fullscreen float color="#4a2c3f">
  <YourCoverArt />
</BookMockup>
```

## Rendering

The canvas renders on demand (`frameloop="demand"`): it draws a frame when a
drag or its damping moves the camera, on zoom, while `autoRotate` or `float`
runs, when a prop changes and on resize - and not otherwise, so an idle mockup
costs no frames. With `pauseWhenOffscreen` (on by default) it also stops
entirely while it is scrolled out of view or the tab is hidden.

Inside a composed `<MockupCanvas>`, a `useFrame` animation of your own does not
by itself cause frames. For motion that runs continuously, render every frame:

```tsx
<MockupCanvas frameloop="always">
  <Spinning> {/* rotates its children in useFrame */}
    <Galaxy>
      <YourApp />
    </Galaxy>
  </Spinning>
</MockupCanvas>
```

For a change you make imperatively - mutating an object from an event
handler, a texture that finished loading - keep the default and ask for a
frame with react-three-fiber's `invalidate()`:

```tsx
import { useRef } from 'react'
import { useThree } from '@react-three/fiber'
import type { MeshStandardMaterial } from 'three'

function Beacon() {
  const material = useRef<MeshStandardMaterial>(null!)
  const invalidate = useThree((state) => state.invalidate)

  // Call it from anywhere: a click, a timer, a texture's onLoad.
  function highlight() {
    material.current.emissiveIntensity = 1
    invalidate()
  }

  return (
    <mesh onClick={highlight}>
      <sphereGeometry args={[0.2]} />
      <meshStandardMaterial ref={material} emissive="#ff8a00" emissiveIntensity={0} />
    </mesh>
  )
}
```

Props and state that flow through React need neither: react-three-fiber
requests a frame whenever it applies a change.

`gl` is merged over the defaults `{ antialias: true, alpha: true,
powerPreference: 'default' }`. The default lets the browser choose the GPU, so
on a dual-GPU laptop a decorative mockup does not wake the discrete one; pass
`gl={{ powerPreference: 'high-performance' }}` when the mockup is the main
event. Leave `alpha` on: the screens are revealed through transparent canvas
pixels, and an opaque canvas hides them (the library warns about it in
development). [GPU and performance](/docs/performance) covers the rest.

## Keyboard controls

With `controls` on, the canvas is focusable, so a keyboard user can do what a
drag does:

| Key | Action |
| --- | --- |
| `←` `→` | Turn the model |
| `↑` `↓` | Tilt the model |
| `+` `-` | Zoom in and out (when `zoom` is on) |
| `Home` | Reset the view |

## Accessibility

The canvas has `role="img"` and an accessible name from `label`. A mockup
names itself after its model ("3D mockup of a Galaxy S phone"); pass `label` to
say what the picture shows in your page's terms:

```tsx
<GalaxyMockup label="The checkout screen of our app on a Galaxy phone">
  <Checkout />
</GalaxyMockup>
```

Screen content is decorative by default (`screenAccessibility="hidden"`):
every screen layer is `aria-hidden` and `inert`, so a demo's headings and
links do not join the page's outline or its tab order. Set
`screenAccessibility="visible"` when the screen carries meaningful text that
appears nowhere else on the page. See [Accessibility](/docs/accessibility).

## Reduced motion

`autoRotate` and `float` are motion nobody asked for, so both stop for visitors
whose system is set to **prefers-reduced-motion: reduce**. The mockup still
renders, and every gesture still works: dragging to orbit, pinching to zoom
and the `+`/`−` buttons are all the visitor's own request, so none of them are
gated. The dot-matrix `LEDText` marquees hold on their first frame for the same
reason.

Nothing is required of you: pass `autoRotate` and `float` as you would
otherwise, and the preference is respected automatically. The one exception
is `time`: on a clock you drive, `autoRotate` and `float` are part of your
timeline - a video's, typically - so the preference is yours to apply there.

If your page has its own motion to gate, the same hook the library uses is
exported:

```tsx
import { usePrefersReducedMotion } from 'react-3d-mockups'

const still = usePrefersReducedMotion()
```
