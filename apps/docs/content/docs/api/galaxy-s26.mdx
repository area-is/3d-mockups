`<Galaxy>` renders a Galaxy device; `<GalaxyMockup>` is the all-in-one version.
Both variants keep true relative sizes and per-model camera architecture - the
6.3″ Galaxy S26 and the 6.9″ Galaxy S26 Ultra, with detail geometry (button
pills, camera island, port cutouts, antenna seams) built from published
specifications and product photography.

## `<Galaxy>` vs `<GalaxyMockup>`

<BareVsMockup object="Galaxy" kind="galaxy" slot="Screen" />

To render this model, pass `variant="s26"`.

```tsx
import { MockupCanvas, Galaxy, GalaxyMockup } from 'react-3d-mockups'

// The one-liner: its own canvas, with lighting, a ground shadow, drag-to-orbit
// controls and a camera already framed on the object.
<GalaxyMockup variant="s26" float style={{ height: 520 }}>
  <YourApp />
</GalaxyMockup>

// The same model with no stage of its own. Inside a canvas you arrange
// yourself it can be posed, animated, lit and joined by anything else.
<MockupCanvas>
  <Galaxy variant="s26" rotation={[0, 0.4, 0]}>
    <YourApp />
  </Galaxy>
</MockupCanvas>
```

## Props

Beyond the [shared screen props](/docs/screen-content) and, on the mockup, the
[shared mockup props](/docs/api):

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `variant` | `'s26' \| 's26ultra'` | `'s26'` | Which Galaxy device: true relative sizes, per-model cameras (S26 triple-lens pill island, Ultra large proud rings + tele column and S Pen silo), and logical resolutions. |
| `orientation` | `'portrait' \| 'landscape'` | `'portrait'` | Landscape lays the device on its side and swaps the virtual display (for example 780×360 on the S26) with upright content. |
| `statusBar` | `boolean \| StatusBarOption` | `false` | Draw the system status bar across the top of the screen. `true` gives the platform's defaults - One UI's, with the clock flush left and the meters at the right inset, clearing the punch hole; an object sets the clock, the meters and the ink (`{{ time: '14:05', battery: 0.42, batteryPercent: true, color: '#1c1c1e' }}`). It is placed from this device's own camera cutout and logical grid, so it lines up with the hardware on every variant. See [Status bar](/docs/screen-content#status-bar). |
| `color` | `string` | `'#101216'` | Back panel. Takes a colorway id from `GALAXY_COLORWAYS[variant]` (see [Colorways](#colorways)), which brings that model's matching metal frame with it, or any CSS color - the frame is then derived from it. |
| `resolution` | `number` | per variant | CSS pixel width of the virtual display; height follows the panel aspect (360 gives 360×780 on the S26). |

## Regions

One region: the screen (bare children). Use the explicit
`<GalaxyMockup.Screen>` slot when you want per-surface overrides -
`surfaceBackground`, `resolution`, `surfaceStyle`. The same slot exists on
the bare `<Galaxy>`.

## Colorways

Pass a colorway id from `GALAXY_COLORWAYS[variant]` for that model's retail
finish; it brings the matching metal frame with it. Any CSS color works for a
custom finish, and the frame is then derived from it, so `color="#2c3344"`
reads as one anodised piece without a second prop. An id wins over a CSS color
of the same name - pass hex if you mean the CSS one.

| Model | Colorway ids (body color) |
| --- | --- |
| Galaxy S26 (`s26`) | `navy` (`#2a3245`), `cobaltviolet` (`#6f6791`), `icyblue` (`#b8cfe0`), `mint` (`#bcd8c6`), `silvershadow` (`#d3d6dd`) |
| Galaxy S26 Ultra (`s26ultra`) | `titaniumsilverblue` (`#a9bdce`), `titaniumblack` (`#15171d`), `titaniumgray` (`#7c8188`), `titaniumwhitesilver` (`#dcdee1`) |
