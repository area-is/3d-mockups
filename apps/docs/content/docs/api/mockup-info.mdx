Every mockup knows how big its live surfaces are. Four ways to ask, depending on
where you're standing.

## `mockupInfo(kind, props)`

The framework-agnostic answer. Pure data in, pure data out - no renderer, no
DOM, no React - so it works in a component, a build script or on a server.

```ts
import { mockupInfo } from 'react-3d-mockups/core'

const info = mockupInfo('galaxy', { variant: 's26', orientation: 'landscape' })

info.kind              // 'galaxy'
info.primary.px        // { width: 780, height: 360 }  - CSS px your content lays out in
info.primary.mm        // { width: 145.2, height: 67.1 } - the physical panel
info.primary.units     // { width: 3.962, height: 1.829 } - three.js world units
info.primary.aspect    // 2.1662
info.mmPerUnit         // 36.66
```

`mockupInfo` is exported from both `react-3d-mockups` and
`react-3d-mockups/core`, and either import works in a Server Component. See
[Measuring in a Server Component](/docs/nextjs#measuring-in-a-server-component).

`props` takes only the props that can actually move a surface - `variant`,
`orientation`, `size`, `openAngle` and `coverScreenUntil` (the foldables:
Fold, Flip and iPhone Duo), `mat` (the poster frame) and `coverage` (the bus
and the van). Colors and transforms can't change a measurement, so they're not
accepted. Omit `props` and you get exactly what the bare component renders
with its defaults - except for the custom panel and custom box, whose `size`
has no default, so `mockupInfo('customPanel', { size: { width: 600, height: 900 } })`
needs it the same way `<CustomPanel>` does.

### Regions

`info.regions` is keyed by region name; `info.list` is the same set flattened in
declaration order.

```ts
const book = mockupInfo('book')
book.regions.cover.px      // { width: 480, height: 720 }
book.regions.spine.mm      // { width: 20.9, height: 232.3 }
book.primary               // === book.regions.cover - where bare children go
```

A region can resolve to an **array**, which means one slot is painted onto
several distinct surfaces - one design, several places it lands:

```ts
const plates = mockupInfo('van').regions.licensePlate
plates.length  // 2 - the van carries a plate at the nose and at the tail
plates[0].mm   // { width: 304.8, height: 152.4 }   both are the US 6 × 12 in
```

The length counts *surfaces*, not sizes: these two are the same rect and it is
still an array of two, because there really are two plates on the van.

Every other region resolves to a single rect. There is no region that takes a
variable number of slot children - every surface has its own name.

### What's in a region

| Field | What it is |
| --- | --- |
| `name` | The region's id, which is also its slot's name: `spine` is `<BookMockup.Spine>`. |
| `label` | A short human label, e.g. `'Front cover'`. |
| `units` | The live rect in three.js world units. |
| `mm` | The same rect in millimetres - the real printed size. |
| `px` | The CSS-pixel viewport your content lays out in, at the default resolution. |
| `pxPerUnit` | CSS pixels per world unit. |
| `resolution` | Default CSS pixel width of the virtual surface. |
| `radius` | Corner rounding, in world units and CSS pixels. |
| `aspect` | `width ÷ height`. |
| `index` | Which surface this is, for a region painted onto several; `0` otherwise. |

The `px` numbers come from the same helpers the renderer feeds its screen
bridge, so what this reports and what actually renders cannot drift apart.

## `Mockup.info()` and `Mockup.regions`

The same answers, hanging off the component you already imported - usually the
one you want, because it's right there in autocomplete next to the slots.

```tsx
import { GalaxyMockup, BookMockup } from 'react-3d-mockups'

GalaxyMockup.info({ variant: 's26ultra' }).primary.px  // { width: 384, height: 833 }
BookMockup.regions  // [{ name: 'cover', label: 'Front cover' }, …]
```

## `useSurface()`

`mockupInfo` answers "how big is an S26 screen?". `useSurface` answers "how big
am I, right now?" - from inside the content, after slot overrides are applied.
Those are different questions the moment a slot changes anything:

```tsx
function Header() {
  const { width, height, pxPerUnit, region } = useSurface()
  return <div style={{ width, height: Math.round(pxPerUnit * 0.1) }} />
}

<GalaxyMockup.Screen resolution={480}>
  <Header />   {/* useSurface() → 480x1040, not the device default 360x780 */}
</GalaxyMockup.Screen>
```

Because the values come from the surface being rendered rather than being
re-derived, they're correct by construction. `useSurface()` throws outside a
mockup surface; use `useSurfaceOptional()` for a component that renders both
inside a mockup and on a normal page - it returns `null` there.

Both return a `SurfaceInfo`:

| Field | What it is |
| --- | --- |
| `region` | Which region the content is rendering into (`'screen'`, `'cover'`…). |
| `width`, `height` | The surface in CSS pixels - the viewport your layout sees. |
| `units` | The same surface in three.js world units, `{ width, height }`. |
| `pxPerUnit` | CSS pixels per world unit on this surface. |
| `resolution` | The resolved `resolution` (CSS pixel width), slot override included. |
| `radius` | Corner rounding in world units: one number, or four (top-left, top-right, bottom-right, bottom-left). |
| `background` | The CSS background painted behind the content. |
| `safeAreaTop` | The strip at the top the status bar and camera cutout cover, in CSS px; `0` on a surface with neither. Also set as the `--mockup-safe-area-top` CSS custom property. See [Laying out under the status bar](/docs/screen-content#laying-out-under-the-status-bar). |

## `react-3d-mockups/catalog.json`

Every kind, pre-measured at build time - `mockupInfo` run over the whole
registry. Useful for docs tables, design-tool plugins and anything that isn't
JavaScript. It holds each device variant in each orientation (open and folded
for the Fold, the Flip and the iPhone Duo), each TV design, the poster frame
with and without a mat, the bus and the van at panel and full coverage, and
every other object at its default size; the custom panel and box, which have
no default size, appear once at an example size.

```ts
import catalog from 'react-3d-mockups/catalog.json'

const fold = catalog.entries.find(
  (e) =>
    e.kind === 'fold' &&
    e.props.variant === 'fold7' &&
    e.props.openAngle === false &&
    e.props.orientation === 'portrait'
)
fold?.regions.find((r) => r.name === fold.primary)?.px // { width: 360, height: 835 } - the cover screen
```

That is a bundler import. Plain Node ESM - a build script run with `node` -
needs the JSON import attribute:

```ts
import catalog from 'react-3d-mockups/catalog.json' with { type: 'json' }
```

An entry is a trimmed `MockupInfo`, not the object `mockupInfo` returns:
`primary` is the primary region's *name*, and `regions` is the flat list in
declaration order (what `info.list` holds), without `pxPerUnit` or `radius`.

```ts
interface Catalog {
  version: number
  kinds: MockupKind[]
  entries: CatalogEntry[]
}

interface CatalogEntry {
  kind: MockupKind
  props: Record<string, unknown> // the props it was measured at, e.g. { variant: 'fold7', openAngle: false, orientation: 'portrait' }
  mmPerUnit: number
  primary: string // the primary region's name, e.g. 'screen'
  regions: {
    name: string
    label: string
    index: number
    units: { width: number; height: number }
    mm: { width: number; height: number }
    px: { width: number; height: number }
    resolution: number
    aspect: number
  }[]
}
```

## Coverage

`MOCKUP_KINDS` is the authoritative list of what can be measured. Every mockup
in the catalog is measurable - 35 kinds.

Vehicles take a `coverage` prop, since a full wrap and a panel ad are different
surfaces:

```ts
mockupInfo('bus', { coverage: 'panel' }).regions.curbSide.mm  // 3657.5 x 761.9 - king-size board
mockupInfo('bus', { coverage: 'full' }).regions.curbSide.mm   // 12160 x 2884.2 - whole elevation
```
