The library has two layers, and every model appears in both.

1. **All-in-one mockups** - a stage and a model in one component, ready to drop
   into a page. Eleven for the devices:

   `GalaxyMockup` · `IPhoneMockup` · `IPhoneDuoMockup` · `FoldMockup` · `FlipMockup` ·
   `LaptopMockup` · `IPadMockup` · `GalaxyTabMockup` · `AppleWatchMockup` ·
   `GalaxyWatchMockup` · `StudioDisplayMockup`

   …and twenty-four for the [objects](/docs/objects):

   `BookMockup` · `MagazineMockup` · `BrochureMockup` · `BusinessCardMockup` ·
   `IDCardMockup` · `GreetingCardMockup` · `PosterFrameMockup` ·
   `VinylRecordMockup` · `ProductBoxMockup` · `MailerBoxMockup` ·
   `MilkCartonMockup` · `ShoppingBagMockup` · `CustomPanelMockup` ·
   `CustomBoxMockup` ·
   `BillboardMockup` · `BusShelterMockup` · `DOOHTotemMockup` ·
   `AFrameSignMockup` · `RollupBannerMockup` · `StorefrontMockup` ·
   `TVSetMockup` · `BusMockup` · `VanMockup` · `SemiTrailerMockup`

2. **Composable parts**: [`MockupCanvas`](/docs/api/mockup-canvas) (the stage)
   plus the bare model behind each mockup, named without the suffix - `Galaxy`,
   `IPhone`, `Fold`, `Book`, `Van`, `TVSet` and so on - for your own
   react-three-fiber scenes. See [Composing scenes](/docs/composing).

   [`TumbleControls`](/docs/api/advanced#tumblecontrols) (the drag-to-orbit
   camera controls) and [`LEDText`](/docs/api/advanced#ledtext) (the
   dot-matrix sign renderer used by the transit models) are exported too,
   along with the [`createMockup`](/docs/api/advanced#createmockup) and
   [slot](/docs/api/advanced#slot-helpers) factories for building a mockup of
   your own. [Advanced exports](/docs/api/advanced) documents them and every
   other export.

Every live example on these pages is a playground: the bar under the canvas has
an input for **every** prop of the mockup above it, grouped into the model's own
props, the [shared screen props](/docs/screen-content), and the
[stage props](/docs/api/mockup-canvas). Each input starts on the value that
example uses, and `×` resets it.

## Shared mockup props

Every `*Mockup` component accepts its device's appearance props, the staging
props below, and:

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `children` | `ReactNode` | - | Screen content: any React node, iframe, or video. |
| `float` | `boolean` | `false` | Gentle floating idle animation for the device. |
| `position` / `rotation` / `scale` | r3f transforms | - | Pose the device on the stage - transforms flow straight through to the device group (`<GalaxyMockup rotation={[0, -0.25, 0]}>`). |

### Staging props

These come from [`MockupCanvas`](/docs/api/mockup-canvas) and work on every
mockup - the ones that change what the mockup looks like on your page, or what
a visitor can do with it:

`controls` · `autoRotate` · `zoom` · `fullscreen` ·
`shadows` · `background` · `camera` · `className` · `style`

…and the ones that decide how it renders and how assistive technology reads
it: `frameloop` · `pauseWhenOffscreen` · `dpr` · `time` · `delayCapture` ·
`gl` · `onCreated` · `label` · `screenAccessibility`. See
[Rendering](/docs/api/mockup-canvas#rendering) and
[Accessibility](/docs/accessibility).

`MockupCanvas` has two more, `freeRotation` and `shadowY`, that a mockup does
not advertise: a mockup's framing already derives the shadow's ground line
from the object's spec, and the orbit clamp is chosen to look right. Compose
[`MockupCanvas`](/docs/api/mockup-canvas) directly when you want them.

## Regions and slots

Bare children always fill a mockup's **primary region** - a phone's screen, a
book's front cover. Objects with more printable surfaces expose each extra
region as a compound slot on the component (`<AFrameSignMockup.Back>`,
`<BookMockup.Spine>`); each mockup's page lists its slots in a Regions
section. Every slot takes per-surface overrides - `surfaceBackground`,
`resolution`, `surfaceStyle` - over the mockup-level defaults.

## Shared screen props

Every device (and therefore every mockup) accepts the screen props documented
in [Screen content](/docs/screen-content): `surfaceBackground`, `surfaceStyle`,
and `resolution`.

Devices also accept all react-three-fiber group props (`position`, `rotation`,
`scale`) when rendered inside a canvas.
