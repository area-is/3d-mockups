The library has two layers:

1. **All-in-one mockups**: `GalaxyMockup`, `IPhoneMockup`, `LaptopMockup`,
   `IPadMockup`, `GalaxyTabMockup`, `AppleWatchMockup`, `GalaxyWatchMockup`, and `StudioDisplayMockup`
   for the devices, plus `BookMockup`, `MagazineMockup`, `BrochureMockup`,
   `BusinessCardMockup`, `PosterFrameMockup`, `BillboardMockup`, and
   `VanMockup` for the [objects](/docs/objects). Each one bundles the stage and
   a model, ready to drop into a page.
2. **Composable parts**: [`MockupCanvas`](/docs/api/mockup-canvas) (the stage)
   plus the bare models (`Phone`, `IPhone`, `Laptop`, `IPad`, `GalaxyTab`, `AppleWatch`,
   `GalaxyWatch`, `StudioDisplay`, `Book`, `Magazine`, `Brochure`, `BusinessCard`,
   `PosterFrame`, `Billboard`, `Van`) for your own react-three-fiber scenes. See
   [Composing scenes](/docs/composing).

Every live example on these pages is a playground: the bar under the canvas has
an input for **every** prop of the mockup above it, grouped into the model's own
props, the [shared screen props](/docs/screen-content), and the
[stage props](/docs/api/mockup-canvas). Each input starts on the value that
example uses, and `×` resets it.

## Shared mockup props

Every `*Mockup` component accepts its device's appearance props, the staging
props below, and:

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `children` | `ReactNode` | - | Screen content: any React node, iframe, or video. |
| `float` | `boolean` | `false` | Gentle floating idle animation for the device. |
| `position` / `rotation` / `scale` | r3f transforms | - | Pose the device on the stage - transforms flow straight through to the device group (`<GalaxyMockup rotation={[0, -0.25, 0]}>`). |

### Staging props

These come from [`MockupCanvas`](/docs/api/mockup-canvas) and work on every
mockup - the ones that change what the mockup looks like on your page, or what
a visitor can do with it:

`controls` · `autoRotate` · `autoRotateSpeed` · `zoom` · `fullscreen` ·
`shadows` · `background` · `camera` · `className` · `style`

`MockupCanvas` has a few more (`freeRotation`, `shadowY`, `dpr`) that tune the
rendering machinery rather than the picture. A mockup does not advertise those:
its framing already derives the shadow's ground line from the object's spec,
and the remaining defaults are chosen to look right. Compose
[`MockupCanvas`](/docs/api/mockup-canvas) directly when you want them.

## Regions and slots

Bare children always fill a mockup's **primary region** - a phone's screen, a
book's front cover. Objects with more printable surfaces expose each extra
region as a compound slot on the component (`<AFrameSignMockup.Back>`,
`<BookMockup.Spine>`); each API page lists its mockup's slots in a Regions
section. Every slot takes per-surface overrides - `surfaceBackground`,
`resolution`, `surfaceStyle` - over the mockup-level defaults.

## Shared screen props

Every device (and therefore every mockup) accepts the screen props documented
in [Screen content](/docs/screen-content): `surfaceBackground`, `surfaceStyle`,
and `resolution`.

Devices also accept all react-three-fiber group props (`position`, `rotation`,
`scale`) when rendered inside a canvas.
