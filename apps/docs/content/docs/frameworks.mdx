WebGL exists only in the browser, so a mockup's 3D picture is always drawn on
the client. Rendering a mockup on the server is safe - it outputs the wrapper
and an empty `<canvas>`, and the picture appears after hydration - but it puts
three.js in the server bundle for nothing. So where a framework renders on the
server, the patterns below load the mockup in the browser only. Wherever it
lives, give its wrapper a fixed height - the mockup fills its parent, and a
reserved box keeps the page from shifting when the canvas appears.

The examples below all load this component:

```tsx title="mockup.tsx"
import { GalaxyMockup } from 'react-3d-mockups'

export default function Mockup() {
  return (
    <GalaxyMockup float>
      <div
        style={{
          height: '100%',
          display: 'grid',
          placeItems: 'center',
          background: '#111',
          color: '#fff',
          fontSize: 32,
        }}
      >
        Hello
      </div>
    </GalaxyMockup>
  )
}
```

For the Next.js App Router, see [Next.js and SSR](/docs/nextjs).

## Vite + React

A Vite single-page app renders only in the browser, so import the mockup
directly. Loading it lazily keeps three.js out of your first chunk:

```tsx title="hero.tsx"
import { lazy, Suspense } from 'react'

const Mockup = lazy(() => import('./mockup'))

export function Hero() {
  return (
    <div style={{ height: 560 }}>
      <Suspense fallback={null}>
        <Mockup />
      </Suspense>
    </div>
  )
}
```

## React Router (framework mode) and Remix

Framework mode renders routes on the server, and `lazy` alone does not stop
that: the mockup's module, three.js included, would load there too. To keep it
in the browser, gate the mockup on hydration: `useSyncExternalStore` reads
`false` on the server and while hydrating, then `true`, so the server HTML and
the first client render agree and the mockup mounts right after.

```tsx title="app/components/hero.tsx"
import { lazy, Suspense, useSyncExternalStore } from 'react'

const Mockup = lazy(() => import('./mockup'))

const subscribe = () => () => {}
const useHydrated = () =>
  useSyncExternalStore(subscribe, () => true, () => false)

export function Hero() {
  const hydrated = useHydrated()
  return (
    <div style={{ height: 560 }}>
      {hydrated && (
        <Suspense fallback={null}>
          <Mockup />
        </Suspense>
      )}
    </div>
  )
}
```

`<ClientOnly>` from `remix-utils` is the same gate as a component. With
`ssr: false` in `react-router.config.ts` (SPA mode) nothing renders on the
server, and the Vite pattern above is enough.

## Astro

Render the component as a React island with `client:only="react"`, which skips
server rendering for it entirely (the `@astrojs/react` integration has to be
installed):

```astro title="src/pages/index.astro"
---
import Mockup from '../components/mockup.tsx'
---

<div style="height: 560px">
  <Mockup client:only="react" />
</div>
```

`client:load` or `client:visible` would render it on the server first as
well, which only adds three.js to the server render: the canvas can draw
nothing there.

## Next.js Pages Router

In the Pages Router, `next/dynamic` with `ssr: false` works directly in a page:

```tsx title="pages/index.tsx"
import dynamic from 'next/dynamic'

const Mockup = dynamic(() => import('../components/mockup'), { ssr: false })

export default function Home() {
  return (
    <div style={{ height: 560 }}>
      <Mockup />
    </div>
  )
}
```
