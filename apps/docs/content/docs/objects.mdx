Beyond phones and laptops, the library models everyday objects whose printable
surface is a live DOM area: design a book cover or a van livery in plain React
(or drop in an `<iframe>`), and it renders as real DOM on the 3D object - no
texture bake, no re-export.

Like the devices, every object is procedurally generated at runtime from real
product dimensions - no GLB files, no hosting, no pop-in.

Each object also has a one-liner `*Mockup` wrapper (`BookMockup`,
`VanMockup`, …) that bundles the stage, camera, and grounded shadow - the same
pattern as the devices.

```tsx
'use client'

import { BookMockup } from 'react-3d-mockups'

export function CoverPreview() {
  return (
    <BookMockup color="#1f3a5f" float>
      <YourCoverArt /> {/* any React node, full bleed */}
    </BookMockup>
  )
}
```

## Printing onto the stock

On the objects whose `color` is the material itself - card, board, paper, a
record jacket, a vehicle's paint under its vinyl - a live surface prints onto
that material: `surfaceBackground` defaults to `color`. Artwork with a
transparent ground shows the stock wherever it leaves clear, and one file
prints on kraft, on white or on a brand dip without being re-exported.

```tsx
<MilkCartonMockup color="#cbab7f">
  <LabelArt /> {/* no background of its own: the kraft shows through */}
</MilkCartonMockup>
```

Set `surfaceBackground` to print onto something else - a white label on a
kraft carton, say.

The samples on these pages are built that way: their artwork has no ground
of its own, so changing `color` in an example changes what it is printed on,
and its type flips between dark and light ink to stay legible. Where `color`
is hardware around a separate sheet - a frame's moulding, a billboard's steel,
a roll-up's cassette - and on a book, whose cover art is its own printed
jacket, the surface still defaults to white.

## Multiple live surfaces

Several objects host more than one surface. Bare children fill the object's
primary surface; name any other region with its compound slot - the same
pattern the devices use. Slots must be direct children of the mockup.
[Regions and slots](/docs/quick-start#regions-and-slots) in the quick start
covers the rules.

```tsx
<ProductBoxMockup rotation={[0, -0.5, 0]}>
  <FrontPanel /> {/* bare children fill the front */}
  <ProductBoxMockup.Right><SidePanel /></ProductBoxMockup.Right>
  <ProductBoxMockup.Top><TopPanel /></ProductBoxMockup.Top>
</ProductBoxMockup>
```

A few of them behave in ways worth knowing:

- **`Brochure`**: left and right are as the viewer of that face sees it, and
  `foldAngle={0}` lays the sheet flat.
- **`Bus`**: the curb-side ad is a queen-size panel that stops short of the
  doors, as on a real bus; `coverage="full"` turns both sides into full wraps.
  `<Bus.DestinationSign>` is the live LED sign above the windshield.
- **`CreditCard`**: the chip, the embossing, the magnetic stripe and the
  signature panel stand over the print as 3D hardware, like the real thing,
  and the back carries the embossing's mirrored impressions.
- **`Van`**: `<Van.LicensePlate>` fills both plates; pass it a plain string
  and it is set on the built-in plate blank.
- **`SemiTrailer`**: `<SemiTrailer.Rear>` sits under a lock-rod overlay, like a
  real rear-door wrap.
- **`MailerBox`**: the packing tape is overlaid on your print.
- **`MilkCarton`**: the screw cap rides over `<MilkCarton.GableFront>`, the same
  way a real spout rides over the print.
- **`ProductBox`**, **`MailerBox`** and **`CustomBox`**: all panels share one
  dpi, so artwork at the same scale lines up across the edges.

## Custom sizes

`CustomPanel` and `CustomBox` take real millimeters via `size` - any
rectangle or box your project needs. The longest edge auto-normalizes to
the stage, so every size fills the default camera while keeping true
proportions. See their component pages for examples.

`ProductBox`, `MailerBox`, `MilkCarton` and `ShoppingBag` accept the same
optional `size` prop (`{ width, height, depth }` in millimeters), so a
300×300×300 mm cube shipper, a 70×195×70 mm quart carton or a slim
100×420×80 mm bottle bag keeps its dressing - tuck flap, tape band, gable
roof, rope handles - in proportion.

## Ground planes

`VanMockup` and `BillboardMockup` ground their shadow at the wheels and pole
base respectively, like `StudioDisplayMockup` does with its stand. The floating
`float` idle animation is available on every object, but reads most natural on
the hand-held print pieces.

## Renderer-agnostic specs

As with the devices, the raw dimensions are exported as plain data from the
`/core` subpath - `BOOK`, `MAGAZINE`, `BROCHURE`, `BUSINESS_CARD`, `ID_CARD`,
`CREDIT_CARD`, `POSTER_FRAME`, `BILLBOARD`, `VAN` and a constant like them for
every other object, plus aspect-ratio constants like `VAN_WRAP_ASPECT`, and
the credit card's embossing font, `STROKE_FONT`, with the `layoutStrokeText`
that sets it:

```ts
import { BOOK, POSTER_FRAME, VAN, VAN_WRAP_ASPECT } from 'react-3d-mockups/core'
```

`/core` carries no `'use client'` banner, so these work in a Server Component
or a build script as well as in the browser. The same numbers will drive the
planned 2D (CSS/SVG) renderers.
