Each `*Mockup` component is a convenience wrapper around two composable parts:
`MockupCanvas` (the stage: canvas, lighting, shadows, controls) and a device
model such as `Galaxy`. Compose them yourself when you want more control.

A bare model is geometry for a scene that already exists, so it always goes
inside a canvas - `MockupCanvas` or a react-three-fiber `<Canvas>` of your
own. Rendered anywhere else it throws
`R3F: Hooks can only be used within the Canvas component!`.

```tsx title="scenes.tsx"
'use client'

import { Canvas } from '@react-three/fiber'
import { Float } from '@react-three/drei'
import { MockupCanvas, Galaxy } from 'react-3d-mockups'

// Option A: the ready-made stage with your own scene arrangement
export function Stage() {
  return (
    <MockupCanvas autoRotate background="#0b0d12">
      <Float>
        <Galaxy color="silvershadow" rotation={[0, -0.4, 0]}>
          <YourApp />
        </Galaxy>
      </Float>
    </MockupCanvas>
  )
}

// Option B: drop the device into a Canvas you already have
export function CustomScene() {
  return (
    <Canvas gl={{ alpha: true }} camera={{ position: [0, 0.5, 7.4], fov: 40 }}>
      <ambientLight intensity={0.7} />
      <directionalLight position={[4, 8, 6]} intensity={1.4} />
      <Galaxy>
        <YourApp />
      </Galaxy>
    </Canvas>
  )
}
```

Devices accept all react-three-fiber group props (`position`, `rotation`,
`scale`), so you can pose several of them in one scene, animate them, or mix
them with your own meshes. Several devices in one canvas also cost less than
several one-liners, each of which is a canvas of its own - see
[GPU and performance](/docs/performance#use-fewer-canvases).

Option B has no orbit controls: those belong to `MockupCanvas`. To get the
same drag-to-orbit, keyboard and pinch-zoom behavior in a canvas of your own, add
[`<TumbleControls />`](/docs/api/advanced#tumblecontrols) inside it. To turn a
composition into a one-liner component of your own, with slots and framing,
see [`createMockup`](/docs/api/advanced#createmockup).

## Your own canvas must stay transparent

Option B works with any react-three-fiber `<Canvas>`, on one condition: the
canvas has to stay transparent. That means an alpha context (`alpha: true`,
which is react-three-fiber's default - do not turn it off) and no background
drawn inside the scene: no `scene.background`, no
`<color attach="background" />`.

The reason is how screens are drawn. A screen's DOM sits *under* the canvas,
and the device clears the canvas to transparent over the glass so the DOM shows
through. An opaque canvas paints over that hole, and every screen disappears -
the device renders, with nothing on it. In development the library logs a
warning, once, when it finds a screen inside an opaque canvas.

To put a color or an image behind the scene, style the canvas element or its
container with CSS instead (`<Canvas style={{ background: '#0b0d12' }}>`) - or
use `MockupCanvas`, whose `background` prop does exactly that.

## Animating inside a composed stage

`MockupCanvas` renders on demand: it draws a frame when something changes, not
sixty times a second. A `useFrame` animation of your own inside it therefore
needs either `frameloop="always"` on the canvas or a call to
react-three-fiber's `invalidate()` whenever the animation moves something.
See [Render only when something changes](/docs/performance#render-only-when-something-changes).

## Transparent background

The WebGL canvas is transparent by default (alpha context, no scene
background), so whatever your page renders behind the mockup shows through.
Set the `background` prop on `MockupCanvas` (any CSS color, gradient, or image
value) when you want the canvas to paint its own backdrop - it is CSS on the
canvas element, so the screens still show through.
