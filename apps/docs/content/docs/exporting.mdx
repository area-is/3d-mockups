## Why `toDataURL()` shows empty screens

A mockup is two layers. The device - body, glass, shadow - is drawn by WebGL
into the canvas. The screen is ordinary DOM that the browser composites with
CSS 3D transforms *under* the canvas, seen through pixels the canvas leaves
transparent. `canvas.toDataURL()` and `toBlob()` read only the canvas's own
pixels - with or without `preserveDrawingBuffer` - so they return the devices
with empty screens.

To capture both layers, capture what the browser composited: a screenshot of
the element, taken by a real browser.

## A PNG with Playwright

This script opens a page, waits for the mockup to render, and screenshots just
the mockup's element at twice the CSS size. Run it against your dev server or
a page you build for the purpose; give the mockup's wrapper something to find
it by (here `id="hero-mockup"`).

```ts title="export-mockup.mts"
import { chromium } from 'playwright'

const browser = await chromium.launch()
const page = await browser.newPage({
  viewport: { width: 1280, height: 900 },
  deviceScaleFactor: 2, // a 2x image
})

await page.goto('http://localhost:3000/', { waitUntil: 'networkidle' })

const mockup = page.locator('#hero-mockup')
await mockup.scrollIntoViewIfNeeded() // an off-screen canvas does not render
await mockup.locator('canvas').waitFor()

// Let fonts and images on the screen load, then give the canvas two frames.
await page.evaluate(async () => {
  await document.fonts.ready
  await new Promise((done) => requestAnimationFrame(() => requestAnimationFrame(done)))
})

await mockup.screenshot({ path: 'mockup.png', omitBackground: true })
await browser.close()
```

Two frames is a guess that usually holds. On a page you control, the mockup
can say when it is done instead: `delayCapture` is called whenever a frame is
on its way that has not been drawn (the renderer starting, a screen whose
content has not landed), and the function it returns is called once it has.
Count them on `window`, and wait for zero:

```tsx title="page.tsx"
declare global {
  interface Window {
    pendingMockupFrames?: number
  }
}

function countPendingFrame() {
  window.pendingMockupFrames = (window.pendingMockupFrames ?? 0) + 1
  return () => {
    window.pendingMockupFrames! -= 1
  }
}

<IPhoneMockup delayCapture={countPendingFrame}>…</IPhoneMockup>
```

```ts
await page.waitForFunction(() => window.pendingMockupFrames === 0)
```

`omitBackground` drops the browser's default white, so the PNG keeps its
transparency wherever your page itself paints nothing behind the mockup.
On a page you capture from, leave `autoRotate` and `float` off, or the pose
depends on when the screenshot lands - and `zoom` and `fullscreen` too, whose
overlay buttons sit inside the element and would be in the picture.

## Video with Remotion

[Remotion](https://www.remotion.dev) renders a React composition in headless
Chrome and captures the page frame by frame, so the screens are in the video
too. Two things make a mockup behave in a render: it has to tell Remotion when
a frame is complete, and every frame has to be a function of the frame number.

```ts title="use-mockup-capture.ts"
import { useCallback } from 'react'
import { useDelayRender } from 'remotion'
import type { DelayCapture } from 'react-3d-mockups'

export function useMockupCapture(): DelayCapture {
  const { delayRender, continueRender } = useDelayRender()
  return useCallback(
    (reason: string) => {
      const handle = delayRender(reason)
      return () => continueRender(handle)
    },
    [delayRender, continueRender]
  )
}
```

```tsx title="turntable.tsx"
import { useCurrentFrame, useVideoConfig } from 'remotion'
import { GalaxyMockup } from 'react-3d-mockups'
import { useMockupCapture } from './use-mockup-capture'

export function Turntable() {
  const frame = useCurrentFrame()
  const { fps } = useVideoConfig()
  const delayCapture = useMockupCapture()
  return (
    <GalaxyMockup
      controls={false}
      delayCapture={delayCapture}
      time={frame / fps}
      autoRotate={6}
      float
      camera={{ position: [0, 0.5, 9 - frame / 60], fov: 40 }}
    >
      <YourApp />
    </GalaxyMockup>
  )
}
```

- **`delayCapture`** holds each frame until the mockup has drawn it: while
  the renderer starts up (react-three-fiber creates it asynchronously), until
  the redraw after a change, and until each screen's content has landed on the
  glass. Without it Remotion captures whatever is on screen, and the first
  frame of a freshly mounted mockup - the start of a `<Sequence>`, or
  wherever a render tab starts - came out with no device, or with a hole
  where the screen belongs, on different frames from one render to the next.
  While it is set the canvas never pauses, so there is no
  `pauseWhenOffscreen` to turn off.
- **`time={frame / fps}`** puts `autoRotate` and `float` on the video's
  clock. Without it they run on the browser's, and Remotion renders frames
  out of order across several tabs, so each tab would land on a different
  point of the spin and the bob. On your clock the same `time` always draws
  the same picture.
- **Everything else from `useCurrentFrame()` too**: `rotation`, `position`
  and `scale`, and any other prop - `openAngle`, `color`, `orientation` - all
  redraw on the frame they change.
- **`camera` is live**: change its `position` or `fov` and the camera moves
  there, still looking at the stage center - the dolly above is a prop. To
  aim somewhere else, move the camera from inside a composed `MockupCanvas`:

  ```tsx
  type Vec3 = [number, number, number]

  function CameraRig({ position, target }: { position: Vec3; target: Vec3 }) {
    const camera = useThree((state) => state.camera)
    const invalidate = useThree((state) => state.invalidate)
    useLayoutEffect(() => {
      camera.position.set(...position)
      camera.lookAt(...target)
      invalidate()
    })
    return null
  }
  ```

- **Screen content** can read `useCurrentFrame()` - the page's context
  reaches the glass. Animate it from the frame, not with timers, CSS
  animations or transitions, which also run on the browser's clock.
- **Keep `frameloop` at its default.** `'demand'` draws the frames a render
  asks for and nothing else. `'always'` keeps every render tab redrawing
  between captures, for nothing, on the same processor that is rendering.
- **WebGL in headless Chrome** needs a GPU backend: render with `--gl=angle`
  on a machine with a GPU. Without one (most CI and cloud machines), use
  `--gl=swangle` - ANGLE over SwiftShader, on the CPU. It is slower but
  workable: on a 4-core machine a 1280×720 phone turntable renders at about
  0.8 s a frame. Try `--concurrency=1` there: every render tab shares
  SwiftShader's one GPU process, and on that machine one tab (74 s for 90
  frames) beat three (106 s).

A complete project - single mockups, a four-device scene with a moving
camera, and animated pattern backgrounds - is in the repository under
[`examples/remotion`](https://github.com/area-is/react-3d-mockups/tree/main/examples/remotion).
