The quickest artwork is a picture. A screen or a printed panel is a real DOM
layer, so an `<img>` that fills it is all it takes: no texture, no UV map, no
re-export when the picture changes. This page is the handful of things worth
knowing when the artwork is a bitmap rather than a component.

Every example below uses a generated image - see
[Preparing generated images](#preparing-generated-images) - and each one is the
actual file the snippet names.

## Fill the surface

Set the image to the surface's full size and let `object-fit: cover` crop it
to the panel's aspect, the way a print shop trims a bleed. The frame is the
composition; the picture just has to cover it.

```tsx
import { PosterFrameMockup } from 'react-3d-mockups'

const cover = { width: '100%', height: '100%', objectFit: 'cover', display: 'block' } as const

<PosterFrameMockup float>
  <img src="/art/poster.webp" alt="" style={cover} />
</PosterFrameMockup>
```

The same one line is a wallpaper on a phone. The status bar draws over it,
exactly as it would on the device, so pick an image with a quiet top edge.

```tsx
<IPhoneMockup variant="pro" statusBar float>
  <img src="/art/wallpaper.webp" alt="" style={cover} />
</IPhoneMockup>
```

<ImageDemo example="wallpaper" />

A product photograph on a laptop is the classic hero shot. A 3:2 photo on a
16:10 panel loses a sliver top and bottom to `cover`; if the crop matters, use
`object-fit: contain` with a `surfaceBackground` that matches the picture's
edges and let it letterbox instead.

```tsx
<LaptopMockup variant="air15" float>
  <img src="/art/coffee.webp" alt="" style={cover} />
</LaptopMockup>
```

## When the aspect already matches

A record sleeve is square, and so is a square image - nothing is cropped and
`cover` and `contain` give the same picture. Check a surface's aspect with
[`mockupInfo`](/docs/api/mockup-info) before you generate or export, and you
can pick a size that needs no cropping at all.

```tsx
mockupInfo('vinylRecord').primary.aspect   // 1
mockupInfo('posterFrame').primary.aspect   // 0.744 - a 2:3 sheet is close
mockupInfo('laptop', { variant: 'air15' }).primary.aspect // 1.545 - shoot 3:2

<VinylRecordMockup float>
  <img src="/art/album.webp" alt="" style={cover} />
</VinylRecordMockup>
```

## A transparent image on the material

A logo is not a full-bleed picture: it sits on the board. Export it with a
transparent background and size it as an element inside the surface.
A bag's surfaces print onto the bag - `surfaceBackground` defaults to its
`color` - so everything the picture leaves clear is the bag, and the same file
prints on kraft, on gloss white or on a charcoal bag without being
re-exported.

```tsx
<ShoppingBagMockup color="#c19a6b" float>
  <div
    style={{
      width: '100%',
      height: '100%',
      display: 'flex',
      alignItems: 'center',
      justifyContent: 'center',
      padding: '18% 14%',
      boxSizing: 'border-box', // keep the padding inside the surface
    }}
  >
    <img src="/art/fox.webp" alt="" style={{ width: '100%', height: 'auto', display: 'block' }} />
  </div>
</ShoppingBagMockup>
```

<ImageDemo example="bag" />

Do not reach for `surfaceBackground="transparent"` to get the board through -
the surface sits under the canvas, so transparent pixels fall through to the
page and read as a hole in the object. The board's colour is already there;
let the image be the transparent thing. [Surface background](/docs/screen-content#surface-background)
has the longer version.

## How big should the image be?

The surface is a viewport of a known size in CSS pixels, and that is the
number to size against - not print resolution. A 444 × 597 mm poster is a
poster in the real world, but on the mockup it is a 540 × 726 CSS px panel,
drawn at whatever device pixel ratio the visitor's screen has. Twice the CSS
size covers a 2× display; anything larger is bytes the page downloads and never
shows.

```ts
import { mockupInfo } from 'react-3d-mockups/core'

const { px } = mockupInfo('posterFrame').primary   // { width: 540, height: 726 }
const target = { width: px.width * 2, height: px.height * 2 } // 1080 × 1452 for a 2× display
```

`mockupInfo` is exported from both `react-3d-mockups` and
`react-3d-mockups/core`, and either import works in a Server Component. See
[Measuring in a Server Component](/docs/nextjs#measuring-in-a-server-component).

`px` follows the `resolution` prop: a larger `resolution` means a larger CSS
viewport for your content to lay out in, at the same physical size on the
object. For a bitmap it changes nothing about how big the image needs to be -
the picture is scaled to the surface either way - so leave `resolution` alone
and size the file to the default `px` grid.

For the record: the images on this page are 1024 px on their short side, which
is a little under 2× for the poster and the phone and comfortably over 1× for
everything, at 70-340 KB each as WebP.

## Preparing generated images

The pictures on this page were made with a text-to-image model at its fastest,
lowest-quality setting, which is plenty for artwork that will only ever be seen
at a few hundred CSS pixels across. Which model matters less than how you ask;
three things made them usable as mockup artwork without editing:

- **Pick the generation size closest to the surface's aspect.** Portrait for
  the poster and the phone, landscape for the laptop, square for the sleeve
  and the logo, so `object-fit: cover` has almost nothing to crop.
- **Ask for no text.** A mockup's surface is the place your own type goes,
  and generated lettering is the first thing that gives a picture away.
- **Ask for a transparent background** where the picture is a mark rather
  than a scene - the fox above - so it prints on the material.

Whatever produced the file, fit it to the surface once, at build time, rather
than shipping the original. This build script crops a source image to the
poster's aspect at twice its CSS size and writes WebP, using
[sharp](https://sharp.pixelplumbing.com):

```ts title="scripts/fit-art.mts"
import sharp from 'sharp'
import { mockupInfo } from 'react-3d-mockups/core'

const { px } = mockupInfo('posterFrame').primary // { width: 540, height: 726 }

await sharp('art-source/poster.png')
  .resize(px.width * 2, px.height * 2, { fit: 'cover' })
  .webp({ quality: 85 })
  .toFile('public/art/poster.webp')
```

The same rules hold for a photograph or an export from a design tool: match
the aspect, leave the type to the surface, and size to the CSS pixel grid.
